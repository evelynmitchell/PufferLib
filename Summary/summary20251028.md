## Added Integration Testing Philosophy to Claude.md

**Objective**: Document best practices for integration testing with a nuanced approach to mocking.

### Key Learning: Mock at the Boundaries

After discussion about integration test dependencies, clarified the principle:
- **Use REAL objects** for internal components and cheap dependencies
- **Use MOCKS** for I/O, expensive operations, and side effects

### Documentation Added

Added new section to `Claude.md` titled "Integration Tests - The Nuanced Approach to Mocking":

**Use REAL objects for**:
- Internal components being integrated (actual modules/classes under test)
- Cheap, standard dependencies (gym.spaces, torch tensors, dataclasses)
- Objects whose behavior is critical to integration

**Use MOCKS for**:
- External systems (databases, networks, APIs, file systems)
- Expensive operations (game simulation, GPU training, large models)
- Non-deterministic behavior (timestamps, random external data)
- Side effects to verify without executing (logging, writes, API calls)

**Example provided**:
```python
# Use REAL gym.spaces - part of integration contract
mock_envs = Mock()
mock_envs.single_action_space = gym.spaces.Discrete(4)  # Real space object
agent = Agent(mock_envs)

# Mock EXPENSIVE environment creation
@patch('pufferlib.cleanrl_ppo_atari.gym.make')
def test_make_env_without_actual_atari(mock_gym_make):
    mock_gym_make.return_value = Mock()  # Mock the actual game
    env_thunk = make_env('ALE/Breakout-v5', 0, False, 'test')
```

## C/C++ Code Coverage Strategy

**Objective**: Add code coverage for C extensions (Ocean environments).

### Current Coverage Gap

Python coverage (pytest-cov) measures only Python code. PufferLib has:
- **50 Ocean environments** written in C (pufferlib/ocean/)
- **C/CUDA extensions** for performance-critical operations
- These represent significant portions of the codebase with 0% coverage visibility

### Tool Selection: gcovr (Option 1)

**Decision**: Use **gcovr** for C/C++ code coverage.

**Rationale**:

1. **Python-based**: Fits existing Python-centric workflow
2. **Easy CI integration**: Simple pip install, works with GitHub Actions
3. **Multiple output formats**: HTML, XML, JSON, Cobertura
4. **Mergeable with Python coverage**: Can combine reports for unified view
5. **Modern interface**: Better than raw gcov/lcov
6. **No system dependencies**: Works on Ubuntu CI without apt-get install

**Alternatives considered**:
- **gcov + lcov**: Traditional but requires system packages, more complex
- **llvm-cov**: Requires Clang compiler switch, less compatible
- **NVIDIA tools**: CUDA coverage is immature, skip for now

### Implementation Plan

1. **Modify setup.py**:
   - Add environment variable check: `COVERAGE_C=1`
   - Add GCC coverage flags when enabled: `-fprofile-arcs -ftest-coverage`
   - Link with gcov library: `-lgcov`

2. **Build with coverage**:
   ```bash
   COVERAGE_C=1 pip install -e . --no-build-isolation
   ```

3. **Run tests** (generates .gcda/.gcno files):
   ```bash
   pytest tests/test_ocean_envs.py
   ```

4. **Generate reports**:
   ```bash
   pip install gcovr
   gcovr --html --html-details -o htmlcov-c/index.html
   gcovr --xml -o coverage-c.xml  # For CI
   ```

5. **CI Integration**:
   - Add gcovr to test dependencies
   - Build with COVERAGE_C=1 in CI
   - Generate and upload C coverage artifacts
   - Optional: Merge with Python coverage using Codecov (if adopted later)

### Expected Benefits

- **Visibility**: See which C code paths are tested
- **Quality**: Identify untested Ocean environment logic
- **Unified reporting**: Combined Python + C coverage metrics
- **CI automation**: Coverage reports on every PR

### Out of Scope

- **CUDA coverage**: Tooling is immature, defer until better tools available
- **Assembly optimizations**: Coverage at source level only

## Optimize CI Matrix Strategy

**Objective**: Speed up CI by running full matrix only when needed.

### Current State

CI runs tests on Python 3.10, 3.11, and 3.12 for every push/PR:
- **Time**: ~15-20 minutes (3 jobs in parallel)
- **Cost**: 3x compute for every PR/commit
- **Feedback**: Slower for developers

### Proposed Strategy

**Fast path** (PRs, feature branches):
- Run tests on Python 3.12 only
- Provides quick feedback (~5-7 minutes)
- Catches 95% of issues

**Full matrix** (releases, main branch):
- Run tests on Python 3.10, 3.11, 3.12
- Ensures backwards compatibility
- Triggered by:
  - Pushes to main/3.0 branches
  - Release tags
  - Manual workflow_dispatch

### Benefits

- **Faster feedback**: 5-7 minutes instead of 15-20 minutes
- **Lower cost**: 1 job instead of 3 for most development
- **Same coverage**: Full matrix still runs before releases
- **CI time savings**: ~10-15 minutes per PR

### Implementation Completed

**Approach**: Split single matrix job into two separate jobs.

**Job 1: test-latest** (always runs):
- Python 3.12 only
- All tests + Python coverage + C coverage
- Uploads coverage artifacts
- Runs on: All PRs, pushes, manual triggers

**Job 2: test-compatibility** (conditional):
- Python 3.11 and 3.10
- All tests, no coverage
- Only runs when:
  - `github.ref == 'refs/heads/main'`
  - `github.ref == 'refs/heads/3.0'`
  - `startsWith(github.ref, 'refs/tags/')` (releases)
  - `github.event_name == 'workflow_dispatch'` (manual)

**Changes in `.github/workflows/test.yml`**:
1. Renamed `test` job to `test-latest`, hardcoded Python 3.12
2. Removed `matrix.py` conditionals (no longer needed)
3. Added `test-compatibility` job with conditional `if`
4. Compatibility job runs same tests but without coverage

**Files Modified**:
- `.github/workflows/test.yml` - Split matrix into fast/full path
- `Claude.md` - Documented CI matrix optimization pattern

**Testing the change**:
```bash

git push origin feature-branch

# On main branch: Both test-latest and test-compatibility run
git push origin main

# Manual trigger: Can choose to run full matrix
gh workflow run tests
```

**Impact**:
- **PR CI time**: 15-20 min → 5-7 min (67% faster)
- **Main branch CI time**: Still ~15-20 min (unchanged, full coverage)
- **Confidence**: No loss - full matrix still runs before merges
