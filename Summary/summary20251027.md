## PufferLib Overview

PufferLib is a **high-performance reinforcement learning framework** designed for training at scale. It's built for speed and flexibility, achieving 1M+ environment steps/second.

### Core Purpose
Production-grade RL training with:
- Parallel environment simulation (thousands of agents simultaneously)
- Fast PPO implementation with V-trace off-policy correction
- Multi-agent and distributed training support
- Extensive environment integration (85+ environments)

### Architecture Highlights

**Key Design Principle**: **Vector-first** - everything operates on batches of agents, not individual steps. All arrays are pre-allocated and updated in-place for zero-copy efficiency.

**Main Components**:

1. **`pufferl.py`** (1,303 lines) - Training orchestrator
   - PPO training loop with GAE/V-trace advantages
   - LSTM/RNN state management
   - Mixed precision, gradient accumulation, torch.compile support

2. **`vector.py`** (925 lines) - Environment parallelization
   - Async multiprocessing with shared memory
   - Zero-copy buffers between workers
   - CPU affinity pinning for performance

3. **`sweep.py`** (714 lines) - Bayesian hyperparameter optimization
   - Gaussian Process-based search
   - Pareto frontier multi-objective optimization

4. **`ocean/`** (64MB, 50 environments) - Custom high-perf environments
   - Written in C with Python bindings
   - Games: Snake, Tetris, Breakout, Go, MOBA, etc.
   - Uses Raylib for graphics, Box2D for physics
   - Extremely fast (~100M+ steps/second for simple games)

5. **`environments/`** (35+ adapters) - External environment wrappers
   - Atari, MuJoCo, Procgen, DeepMind Lab, PettingZoo, etc.

### Language Breakdown

- **Python**: Core framework, training logic, environment wrappers
- **C/C++**: Performance-critical game logic (50 Ocean environments), CPU kernels
- **CUDA**: GPU-accelerated advantage computation
- **Bash**: Build scripts and training runners

### Performance Features

1. **C/CUDA kernels** for advantage computation (10-100x speedup)
2. **Shared memory** between processes (zero-copy)
3. **Asynchronous stepping** - environments run while training updates
4. **In-place array updates** - no allocation overhead
5. **Torch.compile** support for JIT optimization

### Notable Design Patterns

- **Composition over inheritance**: Policies don't need base classes
- **Configuration-driven**: `.ini` files for reproducible experiments
- **Environment emulation layer**: Converts Gym/Gymnasium/PettingZoo to unified interface
- **Modular advantage computation**: Swappable GAE/V-trace/custom implementations

### Entry Points

```bash
# CLI
puffer train puffer_snake
puffer eval puffer_breakout --checkpoint best.pt
puffer sweep puffer_tetris --num_trials 20

# Python API
import pufferlib
pufferlib.pufferl.train('puffer_breakout')
```

### Project Stats
- **Core Python**: ~5K LOC across 6 main modules
- **Total files**: 794 (176 Python, 134 C/C++)
- **Environments**: 50 built-in + 35 adapters
- **Version**: 3.0.0

### Key Insights

The codebase is sophisticated but well-structured, with clear separation between training logic, environment management, and performance optimization. The main complexity is in the vectorization system and the large number of environment implementations.

The "vector-first" design philosophy is central to understanding the codebase - rather than stepping through environments one at a time, everything operates on large batches of agents simultaneously for maximum GPU/CPU utilization.

## Testing Strategy

PufferLib uses a multi-layered testing approach focused on **correctness verification** and **performance benchmarking**, though notably without a CI test suite that runs tests automatically.

### Test Organization

**Location**: `/tests/` directory with 15+ test files

**Main Test Categories**:

1. **Core Functionality Tests** (`test.py` - 300 lines)
   - `test_emulation()`: Validates Gymnasium/PettingZoo environment emulation
   - `test_vectorization()`: Tests Serial, Multiprocessing, and Ray backends
   - Compares vectorized environments against raw single-instance environments
   - Ensures observation/reward/terminal state consistency across backends

2. **API Usage Tests** (`test_api.py` - 137 lines)
   - Tests error handling for incorrect API usage
   - Validates `APIUsageError` and `InvalidAgentError` exceptions
   - Tests both sync and async vectorization APIs
   - Ensures proper validation of actions, observations, and agent names

3. **Performance Benchmarking** (`test_performance.py` - 329 lines)
   - `profile_emulation()`: Measures emulation overhead vs raw environments
   - `profile_puffer()`: Benchmarks vectorization backends (Serial, Multiprocessing, Ray)
   - Compares against Gymnasium and Stable-Baselines3 vectorization
   - Reports: SPS (steps per second), overhead %, reset time %, step variance
   - Uses `TimedEnv` wrapper to separate environment time from framework time

4. **PyTorch Utilities Tests** (`test_pytorch.py` - 212 lines)
   - Uses **pytest** with parametrized tests
   - Tests `nativize_dtype()`: Structured dtype conversion for observations
   - Tests `nativize_tensor()`: Byte array to typed tensor conversion
   - Validates torch.compile compatibility (no graph breaks)
   - Tests complex nested Dict/Tuple observation spaces

5. **C/CUDA Extension Tests** (`test_extensions.py` - 96 lines)
   - Tests flatten/unflatten operations for nested spaces
   - Benchmarks pack/unpack performance with timeit
   - Tests concatenate/split operations for batched data

6. **LSTM/RNN Tests** (`test_puffernet_linearlstm.py`)
   - Validates LSTM wrapper correctness
   - Tests against saved model weights (binary .bin files)
   - Uses Cython extensions for performance-critical RNN code

7. **Hyperparameter Sweep Tests** (`test_custom_sweep.py`)
   - Tests Bayesian optimization (Protein algorithm)
   - Validates Gaussian Process-based hyperparameter suggestions
   - Tests multi-objective optimization with Pareto frontiers

8. **Rendering Tests** (`test_render.py`)
   - Manual visual testing script (not automated)
   - Tests different render modes: human, rgb_array, ansi
   - Validates rendering across different environment types

### Testing Methodology

**Comparison-Based Testing**: Most tests compare PufferLib's behavior against:
- Raw environment outputs (Gymnasium/PettingZoo)
- Other vectorization libraries (Gymnasium AsyncVectorEnv, SB3 SubprocVecEnv)
- Known-good reference implementations

**Key Testing Patterns**:

1. **Exact Equality Checks**:
   ```python
   assert np.all(raw_rewards == vec_rewards)
   assert np.all(raw_terminals == vec_terminals)
   ```

2. **Space Sample Comparison**:
   ```python
   compare_space_samples(raw_ob, puf_ob)  # Deep comparison of nested structures
   ```

3. **Performance Profiling**:
   ```python
   sps = agent_steps / elapsed_time  # Steps per second
   overhead = 100 * (puf_time - raw_time) / puf_time
   ```

4. **Tolerance-Based Tests**:
   ```python
   assert_near(pytorch_output, cython_output, tolerance=1e-4)
   ```

- Tests must be run manually: `python tests/test.py`
- Individual test files are self-contained scripts
- Performance tests require significant runtime (10-60 seconds per profile)

### Test Infrastructure

**Mock Environments** (`pufferlib/environments/test.py`):
- `MOCK_SINGLE_AGENT_ENVIRONMENTS`: Gymnasium test environments
- `MOCK_MULTI_AGENT_ENVIRONMENTS`: PettingZoo test environments

**Test Utilities**:

### Notable Gaps

1. **No CI Test Automation**: Tests exist but aren't run automatically on PRs/commits
2. **No Coverage Metrics**: No code coverage reporting
3. **Manual Performance Tests**: Benchmarking requires manual execution
4. **Limited Integration Tests**: Most tests focus on unit-level correctness

### Testing Philosophy

PufferLib prioritizes:
1. **Correctness**: Ensuring vectorized/emulated envs match raw behavior exactly
2. **Performance**: Measuring overhead and SPS across different backends
3. **Compatibility**: Testing against multiple environment APIs (Gym, Gymnasium, PettingZoo)
4. **Regression Testing**: Comparing against reference implementations

The testing approach is **validation-focused** rather than TDD-style, with emphasis on ensuring the high-performance wrappers don't change environment semantics.

## Adding a New Environment to PufferLib

PufferLib supports three approaches for adding environments, depending on your needs and performance requirements.

### Documentation Status
⚠️ **Limited Official Documentation**: The README directs to puffer.ai, but comprehensive environment creation guides are not currently available. The best documentation is in the **examples folder** and **existing environment implementations**.

### Approach 1: Pure Python PufferEnv (Simple, Fast Enough)

**Best for**: Custom RL environments, moderate performance needs (~100K-1M steps/sec)

**Template**: `examples/puffer_env.py`

**Key Requirements**:
1. Inherit from `pufferlib.PufferEnv`
2. Define `single_observation_space`, `single_action_space`, `num_agents`
3. Implement `reset()` and `step()` with in-place array updates
4. Use pre-allocated buffers: `self.observations`, `self.rewards`, `self.terminals`, `self.truncations`

**Example**:
```python
import gymnasium
import pufferlib

class MyEnv(pufferlib.PufferEnv):
    def __init__(self, num_envs=1, buf=None, seed=0):
        # Define spaces for a SINGLE agent
        self.single_observation_space = gymnasium.spaces.Box(
            low=0, high=255, shape=(84, 84, 3), dtype=np.uint8)
        self.single_action_space = gymnasium.spaces.Discrete(4)
        self.num_agents = num_envs  # Total agents across all environments

        super().__init__(buf)  # Allocates buffers

        # Your custom initialization here
        self.game_state = ...

    def reset(self, seed=0):
        # Reset environment state
        # Update self.observations[:] in-place
        self.observations[:] = ...  # Shape: (num_agents, 84, 84, 3)
        return self.observations, []

    def step(self, actions):
        # Process actions (shape: num_agents)
        # Update arrays IN-PLACE (critical for performance!)
        self.observations[:] = ...
        self.rewards[:] = ...
        self.terminals[:] = ...
        self.truncations[:] = ...

        info = []  # List of dicts (optional)
        return self.observations, self.rewards, self.terminals, self.truncations, info

    def close(self):
        # Cleanup if needed
        pass
```

**Critical Design Patterns**:
- ✅ **In-place updates**: Modify `self.observations[:]`, not `self.observations = ...`
- ✅ **Vector-first**: All operations on batches of agents
- ✅ **Pre-allocated buffers**: Passed via `buf` parameter and allocated by `super().__init__(buf)`

### Approach 2: Wrapping Existing Environments (Easiest)

**Best for**: Using Gymnasium, Gym, or PettingZoo environments

**Templates**:
- `examples/gymnasium_env.py` - Wrap Gymnasium environments
- `examples/gym_env.py` - Wrap legacy Gym environments
- `examples/pettingzoo_env.py` - Wrap multi-agent PettingZoo environments
- `examples/structured_env.py` - Complex observation spaces (Dict, Tuple)

**Example (Gymnasium)**:
```python
import gymnasium
import pufferlib.emulation

class MyGymnasiumEnv(gymnasium.Env):
    def __init__(self):
        self.observation_space = gymnasium.spaces.Box(low=-1, high=1, shape=(4,))
        self.action_space = gymnasium.spaces.Discrete(2)

    def reset(self, seed=None):
        return self.observation_space.sample(), {}

    def step(self, action):
        obs = self.observation_space.sample()
        reward = 0.0
        done = False
        truncated = False
        info = {}
        return obs, reward, done, truncated, info

# Wrap it as PufferEnv
puffer_env = pufferlib.emulation.GymnasiumPufferEnv(MyGymnasiumEnv)
```

**PettingZoo Multi-Agent**:
```python
puffer_env = pufferlib.emulation.PettingZooPufferEnv(my_pettingzoo_env)
```

**Observation Flattening**:
- PufferLib automatically flattens Dict/Tuple observations to byte arrays
- Use `pufferlib.pytorch.nativize_tensor()` in your model to unflatten

### Approach 3: High-Performance C Environments (Advanced, 10M+ steps/sec)

**Best for**: Ultra-high performance simulation (e.g., Snake at 100M+ steps/sec)

**Templates**: Any environment in `pufferlib/ocean/` (50 examples)
- **Simplest**: `pufferlib/ocean/chain_mdp/` - Minimal C environment
- **Complex**: `pufferlib/ocean/snake/` - Full-featured with Raylib rendering

**File Structure**:
```
pufferlib/ocean/my_env/
├── my_env.py          # Python wrapper (PufferEnv subclass)
├── binding.c          # Python-C interface (uses env_binding.h)
├── my_env.c           # Core game logic (C)
├── my_env.h           # Header with Env struct and functions
└── README.md          # Environment description
```

**Key Components**:

**1. Python Wrapper** (`my_env.py`):
```python
import pufferlib
from pufferlib.ocean.my_env import binding

class MyEnv(pufferlib.PufferEnv):
    def __init__(self, num_envs=1, buf=None, seed=0, **kwargs):
        self.single_observation_space = gymnasium.spaces.Box(...)
        self.single_action_space = gymnasium.spaces.Discrete(...)
        self.num_agents = num_envs

        super().__init__(buf)

        # Initialize C environments (bindings auto-created)
        self.c_envs = binding.vec_init(
            self.observations, self.actions, self.rewards,
            self.terminals, self.truncations, num_envs, seed, **kwargs)

    def reset(self, seed=0):
        binding.vec_reset(self.c_envs, seed)
        return self.observations, []

    def step(self, actions):
        self.actions[:] = actions
        binding.vec_step(self.c_envs)
        return self.observations, self.rewards, self.terminals, self.truncations, []

    def close(self):
        binding.vec_close(self.c_envs)
```

**2. C Binding** (`binding.c`):
```c
#include "my_env.h"
#define Env MyEnv
#include "../env_binding.h"  // Provides vec_init, vec_step, etc.

static int my_init(Env* env, PyObject* args, PyObject* kwargs) {
    env->custom_param = unpack(kwargs, "custom_param");
    return 0;
}

static int my_log(PyObject* dict, Log* log) {
    assign_to_dict(dict, "score", log->score);
    return 0;
}
```

**3. Core Logic** (`my_env.h` and implementation):
```c
typedef struct {
    // Observation/action/reward buffers (set by binding.c)
    uint8_t* observations;
    int32_t* actions;
    float* rewards;
    bool* terminals;
    bool* truncations;

    // Custom state
    int custom_param;
    GameState* game_state;

    // Logging
    int tick;
    Log log;
} MyEnv;

void c_reset(MyEnv* env);
void c_step(MyEnv* env);
void c_render(MyEnv* env);  // Optional
```

**Performance Tips** (from `snake/README.md`):
1. **Memory views**: Access numpy arrays as C arrays (zero-copy)
2. **No memory management**: All data allocated by NumPy, passed to C
3. **No Python callbacks**: Pure C execution path
4. **Compile with optimizations**: See `setup.py` for Cython annotations

**Common Binding Functions** (from `env_binding.h`):
- `vec_init(obs, acts, rews, terms, truncs, num_envs, seed, ...)` - Initialize
- `vec_reset(envs, seed)` - Reset all environments
- `vec_step(envs)` - Step all environments
- `vec_log(envs)` - Get logging info
- `vec_render(envs, idx)` - Render specific environment
- `vec_close(envs)` - Cleanup

### Common Pitfalls

❌ **Don't**: `self.observations = new_array`
✅ **Do**: `self.observations[:] = new_values`

❌ **Don't**: Return per-environment observations
✅ **Do**: Return batched arrays (num_agents, ...)

❌ **Don't**: Allocate new arrays every step
✅ **Do**: Use pre-allocated buffers

❌ **Don't**: Process agents sequentially
✅ **Do**: Vectorize operations across all agents

### Common Issues & Solutions

**Issue**: `ModuleNotFoundError: No module named 'gymnasium'`
**Solution**:
```bash
# Using pip
pip install gymnasium

# Using uv (faster)
uv pip install --system gymnasium
```

**Issue**: Gym deprecation warning
**Solution**: This is expected - PufferLib maintains compatibility with both Gym and Gymnasium. The warning doesn't affect functionality. To silence it:
```python
import warnings
warnings.filterwarnings("ignore", category=DeprecationWarning)
```

**Issue**: NumPy 2.0 compatibility
**Solution**: PufferLib works best with NumPy < 2.0:
```bash
pip install "numpy<2.0"
```
